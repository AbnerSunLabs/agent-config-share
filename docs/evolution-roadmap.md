# 个人 AI 研发工作流演进路线

## 1. 演进原则

工作流采用“先契约、再增强、后强制、最终平台化”的顺序。每个版本必须独立可用，只有上一版本通过真实任务验证后，才引入下一层复杂度。

升级依据来自实际失败数据，不来自功能清单。没有真实痛点支撑的状态机、Hook、并行调度和可观测性均暂缓。

## 2. V1：跨 Agent 文档契约

### 建设内容

- 核心生命周期与状态转换。
- 规划设计人工确认门禁。
- AI 自主实现、验证、Review、修复和 L2 交付。
- Fast、Standard、Governed 三条路径。
- 项目配置、任务和 Review 模板。
- Codex、Claude Code、Cursor 薄适配入口。

### 明确不做

- 不开发状态引擎。
- 不开发 Hook。
- 不自动调度多个 Agent。
- 不自动 Push、创建 PR、合并或部署。
- 不要求安装任何插件。

### 退出条件

至少使用 V1 完成一批具有代表性的真实任务，并能回答：

- 哪些步骤最常被跳过？
- 哪些字段经常无价值或重复？
- 哪些验证命令难以稳定执行？
- Review 的主要误报和漏报是什么？
- AI 在哪些情况下仍会频繁打断用户？

建议先观察 10 至 20 个包含 Fast、Standard 和 Governed Path 的任务，再决定下一版范围。

## 3. V1.1：宿主能力适配

### 建设内容

- 将核心能力映射到 Codex、Claude Code、Cursor 的现有能力。
- Claude Code 优先验证 `feature-dev`、`code-review`、`pr-review-toolkit`、`commit-commands` 和 `claude-md-management`。
- 按项目启用 TypeScript、Python、Go 等 LSP。
- 固化独立 Reviewer 的优先级和不可用时的降级路径。

### 进入条件

- V1 字段和门禁在真实任务中基本稳定。
- 已确认主要 Agent 宿主及其能力边界。
- 已收集至少一轮跨 Agent 接力问题。

### 退出条件

- 同一个任务包可以由两个不同 Agent 读取和继续执行。
- Claude 插件缺失时仍可按核心流程完成任务。
- 宿主适配文件没有复制和分叉核心规则。

## 4. V2：Skill 与质量自动化

### 建设内容

- 将稳定流程封装为 `plan`、`build`、`review` 三个核心 Skill。
- 统一 Finding 结构和 Review Profile。
- 引入最多 3 轮的自动修复循环。
- Governed Path 接入安全和迁移专项检查。
- 将高频、稳定、可机械判断的规则升级为少量 Hook。

### Claude Code 可选能力

- `ralph-loop`：受限修复循环。
- `security-guidance`：实现期实时安全提示。
- `claude-security`：Governed Path 深度安全审计。
- `hookify`：将已稳定的 Guardrail 转为 Hook。
- `code-simplifier`：测试通过后的可选简化，不作为完成门禁。

### 进入条件

- 某个步骤反复出现同一种人为提醒。
- 某项规则具有明确输入、判定和输出。
- 自动化失败时存在可靠降级路径。

### 明确不做

- 不因存在 Hook 就移除最终证据核验。
- 不把主观风格偏好变成阻断性 Hook。
- 不允许自动修复循环改变审批基线。

## 5. V3：状态、恢复与可观测性

### 建设内容

- 持久化工作流状态和阶段历史。
- 跨会话恢复和幂等状态转换。
- Review 聚合、去重、置信度和限流。
- Session 成本、失败阶段和返工次数统计。
- 可选的多 Agent 调度和文件范围协调。
- 将成熟能力打包为可安装 Plugin。

### 进入条件

- Markdown 状态无法可靠支撑跨会话或并行任务。
- 多 Reviewer 产生了明显重复和噪声。
- Hook、Skill 和适配器数量已经需要统一安装与版本管理。
- 已证明恢复、审计或指标能够解决真实损失。

### 架构约束

- 工作流实例不能只按项目目录唯一，应考虑 branch、worktree 或显式 task id。
- 状态引擎只记录事实和状态，不取代仓库中的任务产物。
- 自动化组件故障时，核心文档流程仍可运行。

## 6. 最终态：个人 AI SDLC

最终系统由五个平面组成：

1. **人工控制面**：目标、设计、授权、风险与发布决策。
2. **AI 执行面**：探索、实现、验证、Review、修复与交付。
3. **质量治理面**：DoD、独立 Reviewer、安全门禁和证据校验。
4. **宿主适配面**：Codex、Claude Code、Cursor 和未来 Agent 的能力映射。
5. **学习进化面**：失败数据、规则晋升、Skill 评估和流程版本管理。

最终态不是让 AI 获得无限权限，而是让 AI 在明确授权边界内最大化自主性：人工只处理方向、风险和例外，AI 对执行闭环和完成证据负责。

## 7. 迭代决策表

| 观察到的问题 | 优先升级方式 |
|---|---|
| Agent 经常漏读流程 | 加强宿主薄适配入口 |
| 经常漏填同一任务字段 | 改进任务模板或增加 Skill |
| 经常无证据宣称完成 | 增加 verifier 门禁，稳定后升级 Hook |
| Review 漏报 | 增加专项 Review Profile 或独立 Reviewer |
| Review 噪声过多 | 增加证据要求、置信度和聚合去重 |
| 修复反复失败 | 限制循环次数并改进根因报告 |
| 跨会话任务丢失 | 引入轻量状态持久化 |
| 多 Agent 文件冲突 | 引入任务拆分和文件范围协调 |
| 跨项目安装成本高 | 打包 Plugin 并做版本管理 |
